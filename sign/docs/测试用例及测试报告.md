## 6. 已知限制与建议

1. **手机网页相机需要 HTTPS 或 localhost**：局域网 HTTP 下 `getUserMedia` 会被浏览器拒绝，已提供"从相册选择"作为兜底（会调起系统相机）。需要实时取景请配置 HTTPS。
2. **实体打印未验证**：测试环境无打印机，仅验证 A5 页面渲染；上线前需用现场打印机试打并勾选"背景图形"。
3. **二维码实扫**：编码器已通过独立解码、BCH、RS 校验子验证；建议用 iOS/Android 各一款手机实扫复核（验收清单已列）。
4. **触控笔手感**：冒烟使用鼠标事件验证逻辑，压感与笔锋需用现场触控笔实测，必要时调整 `public/js/lib/signpad.js` 的笔宽系数。
5. **4K 性能**：自适应逻辑已就绪，但无头环境无法代表 GPU 表现；建议 4K 现场把展示数量设为 40–72 并连续签名 30 分钟观察。
6. **单机容量**：单文件 JSON 适合单场数千条签名；若需多会场汇总或数万条历史数据，按部署文档第 9 节替换为 MySQL/MongoDB。
7. **浏览器兼容**：仅验证 Chromium 内核（Chrome/Edge）。Safari 手机端已验证布局与交互代码路径，未做真机回归；不建议使用 IE 或旧版国产双核浏览器。
8. **并发**：单进程 Node 服务，实测 16 条提交与 3 个 WS 连接稳定；建议单场并发不超过 300 台手机同时在线（现场 Wi-Fi 通常是瓶颈）。

## 8. 回归记录

### 2026-10-23：二维码指向虚拟网卡，手机无法打开

- **现象**：现场电脑装有 VMware，二维码编码出的地址是 `192.168.189.1`（VMnet1），手机访问超时。
- **原因**：`lanAddresses()` 直接取 `os.networkInterfaces()` 中第一个非回环 IPv4，未区分虚拟网卡；该机器真实 Wi-Fi 地址为 `10.206.118.146`。
- **修复**：
  1. 新增网卡评分：Wi-Fi / 有线 +30，私网地址 +16~20，VMware / Hyper-V / VirtualBox / Docker / WSL 等 -100，APIPA -60，按分数排序；
  2. 二维码 / 海报改用评分最高的地址；用 `localhost` 或虚拟网卡地址打开大屏时自动切换；
  3. 后台「活动配置」新增地址下拉（数据来自 `GET /api/network`），并实时显示"当前二维码指向"，选中虚拟网卡会给出红色警告；
  4. 大屏二维码下方直接显示 `IP:端口`，现场可肉眼核对；
  5. 新增 `开放防火墙端口.bat`，一键放行端口（Windows 常把现场 Wi-Fi 识别为"公用网络"而拦截入站）。
- **验证**：`/api/config.mobileUrl` 由 `http://192.168.189.1:8123/mobile` 变为 `http://10.206.118.146:8123/mobile`；`lanAddresses()` 首项为 WLAN；新增 3 个网络用例 + 1 个接口用例，测试总数 41，全部通过。
- **待现场复核**：手机实扫二维码打开页面（受测试环境无手机限制）。

### 2026-10-23：实时人数口径（当前展示人数，删除即减少）

- **需求**：实时显示"已有几人签名"，删除后人数同步减少。
- **调整**：
  1. 大屏待机与底部提示的人数由"今日提交数"改为"当前展示中（approved）人数"；
  2. 大屏在收到 `signature:remove` / `wall:clear` 时立即用广播里的 `stats` 刷新，不再等 15 秒定时统计；
  3. 手机端对任意带 `stats` 的推送实时更新人数；
  4. 后台概览的"今日上墙"改名为"今日新增"（累计口径），"展示中"仍为当前人数。
- **验证**：接口测试新增"通过 +1 / 隐藏 -1 / 清屏归零、累计不清零"断言；冒烟脚本在大屏上隐藏一条签名后校验人数 15 → 14。

### 2026-10-23：跨网络访问（公网 / 隧道）

- **需求**：设备与网络不同（手机 4G、甲方异地）也能扫码签名、打开管理后台。
- **说明**：局域网私有地址在技术上无法跨网络路由，必须提供一个公网入口（公网服务器或内网穿透），这不是代码开关能绕过的。
- **实现**：
  1. 反向代理支持：读取 `X-Forwarded-Proto` / `X-Forwarded-Host`，二维码与后台链接自动使用外部域名，不再退回内网地址；
  2. HTTPS 代理下会话 Cookie 自动带 `Secure`；
  3. 后台「对外访问地址」支持填写域名根地址（自动规范化为 `/mobile`），并返回 `publicBaseUrl` 供「其他设备访问」二维码使用；
  4. 新增 `deploy/` 套件：Nginx 配置、systemd 服务、公网服务器 / Cloudflare Tunnel / ngrok / frp / 端口映射说明。
- **验证**：新增接口用例模拟反向代理头，`mobileUrl` 为 `https://wall.example.com/mobile`、`publicBaseUrl` 为 `https://wall.example.com`、Cookie 带 `Secure`；域名根地址规范化正确；测试总数 41，全部通过。
