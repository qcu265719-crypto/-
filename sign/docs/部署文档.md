## 3. 硬件与网络建议

### 3.1 大屏与触摸

| 场景 | 建议 |
| --- | --- |
| 分辨率 | 1920×1080 起步；4K（3840×2160）需在后台把「最多同时展示」调到 40–72，页面会自动降低渲染倍率保帧 |
| 触摸方式 | 红外触摸框、电容触摸一体机均可（基于 Pointer Events，支持多点） |
| 屏幕比例 | 16:9 最佳；带鱼屏 / 竖屏可用，但海报与面板按横屏设计 |
| 亮度 | 室内 400 nit 以上；户外需高亮屏并避免阳光直射（水墨深色背景在强光下对比度会下降） |
| 主机 | 建议独立小主机（i5 / 8 GB / 集显即可），关闭休眠与自动更新 |

### 3.2 摄像头与打印机（可选）

- 大屏拍照：USB 摄像头，浏览器首次使用需在弹窗中允许（`localhost` 属于安全上下文，可用）。
- 打印留念：系统安装打印机驱动，打印页为 A5 竖版；浏览器打印对话框需允许弹出（后台 "大屏支持打印留念" 开启后，详情面板出现「打印留念」）。
- 建议把 Chrome 的默认打印机、边距、背景图形（必须勾选"背景图形"）提前设置好并演练一次。

### 3.3 网络方案

| 方案 | 适用 | 做法 | 注意 |
| --- | --- | --- | --- |
| 现场局域网 | 推荐，最稳定 | 一台笔记本/小主机开热点或接现场路由器，运行服务 | 手机与大屏必须同一网段；关闭路由器"AP 隔离" |
| 现场有线 + Wi-Fi | 大屏有线，手机 Wi-Fi | 大屏访问 `localhost`，手机访问局域网 IP | 二维码自动使用局域网 IP |
| 公网服务器 | 多会场 / 远程查看 | 部署到云主机，Nginx 反代 + 域名 | 必须配 HTTPS，否则手机相机被浏览器禁用 |

> **二维码地址如何选择。** 服务启动时会自动挑选"手机最可能连上"的网卡：优先 Wi-Fi / 有线，自动排除 VMware、Hyper-V、VirtualBox、Docker、WSL 等虚拟网卡，并优先私网地址。启动日志会打印 `二维码地址 192.168.x.x（WLAN）`。现场若有多块网卡，请在后台「活动配置 → 对外访问地址」下拉选择正确的一项。

> **重要：手机摄像头限制。** 浏览器要求 `getUserMedia` 运行在安全上下文（HTTPS 或 localhost）。局域网 `http://192.168.x.x` 下，手机端「打开相机」会被浏览器拒绝，页面会提示改用「从相册选择」——该入口会调起系统相机，仍可正常拍照留影。若必须使用网页实时取景，请按第 6 节配置 HTTPS。

### 3.4 端口

默认 `8080`，可用环境变量修改：

```powershell
$env:PORT=9000; node server/index.js
```

Windows 防火墙放行（管理员 PowerShell）：

```powershell
New-NetFirewallRule -DisplayName "SignatureWall 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

## 4. 安装与启动

### 4.1 Windows

1. 安装 Node.js（LTS，安装时勾选 Add to PATH）。
2. 将 `sign` 目录放到任意位置，例如 `D:\sign`。
3. 首次使用建议双击 `开放防火墙端口.bat`（会弹出管理员授权），放行 8080 端口，否则手机可能连不上。
4. 双击 `启动签名墙.bat`，或在该目录打开 PowerShell 执行 `node server/index.js`。
5. 浏览器打开 `http://localhost:8080/`，确认待机画面与二维码正常。

### 4.2 Linux（Ubuntu 示例）

```bash
cd /opt/sign
node server/index.js            # 前台试运行
```

长期运行建议用 systemd：

```ini
# /etc/systemd/system/signature-wall.service
[Unit]
Description=Signature Wall
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/sign
Environment=PORT=8080
ExecStart=/usr/bin/node /opt/sign/server/index.js
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now signature-wall
sudo journalctl -u signature-wall -f
```

### 4.3 大屏浏览器设置（推荐）

用 Chrome 的 kiosk 模式打开，避免地址栏与误触：

```bat
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --kiosk --app=http://localhost:8080/ ^
  --disable-pinch --overscroll-history-navigation=0 ^
  --incognito
```

活动当天：

- 关闭系统休眠 / 屏保 / 自动更新重启。
- 在页面里按 `F` 切换全屏；`Esc` 关闭面板。
- 浏览器缩放保持 100%，页面自身会按屏幕大小自适应。
- 打开浏览器「允许自动播放」与「允许摄像头」，并关闭弹窗拦截（打印窗口）。

## 5. 活动前配置（后台）

访问 `http://<大屏地址>:8080/admin`，默认口令 `admin123`。

1. **系统状态 → 修改管理员口令**（至少 8 位，务必修改）。
2. **活动配置 → 活动信息**：主标题、副标题、主办方、场地、日期（会同步到大屏、手机端、海报）。
3. **视觉与主题**：背景主题（水墨晨曦 / 暖霞山色 / 星河夜色）、主强调色、纸张色。
4. **大屏行为**：签名墙形态（地球仪 / 星空 / 气泡）、最多同时展示数量、待机返回秒数、显示二维码 / 留言条、音效。
5. **互动设置**：大屏拍照留影（需摄像头）、打印留念、允许留言。
6. **审核设置**：自动通过（关闭后需人工审核）、敏感词命中策略（打码 / 拒收）、昵称与留言长度。
7. **敏感词**：按活动场景增删词库，支持批量导入、导出。
8. **对外访问地址**：默认「自动选择」会挑手机可达的 Wi-Fi / 有线网卡。若自动结果不对（例如现场有多块网卡），在下拉框中选择对应地址，或在下方输入完整 URL（如 `https://wall.example.com/mobile`）；清空输入框即恢复自动。页面下方会实时显示"当前二维码指向"。二维码与海报都使用该地址。
9. 回到「概览」点击**一键清屏**，清除示例数据（自动备份到 `data/exports/`）。

> 建议在活动开始前用 3–5 台不同型号手机各走一遍：扫码 → 签名 → 留言 → 拍照 → 提交 → 保存海报。

## 6. 公网 / HTTPS 部署（Nginx 示例）

WebSocket 必须同时反代升级头：

```nginx
server {
    listen 443 ssl http2;
    server_name wall.example.com;

    ssl_certificate     /etc/nginx/cert/fullchain.pem;
    ssl_certificate_key /etc/nginx/cert/privkey.pem;

    client_max_body_size 12m;

    location / {
        proxy_pass         http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_read_timeout 120s;
    }
}
```

配置 HTTPS 后：

- 手机端「打开相机」可正常调用前置摄像头。
- 海报二维码应指向 `https://wall.example.com/mobile`（后台「对外访问地址」填写 `https://wall.example.com` 即可，保存时自动补 `/mobile`）。
- 后台「其他设备访问」二维码同样使用该地址，任何网络都能扫码打开后台。
- 会话 Cookie 在 HTTPS 下自动带 `Secure` 标记。
- 程序会读取 `X-Forwarded-Proto` / `X-Forwarded-Host`，因此二维码与后台链接始终使用外部域名，而不是内网 `127.0.0.1`。

> 现成的 Nginx、systemd 与隧道配置见仓库 `deploy/` 目录（`deploy/README.md` 含公网服务器、Cloudflare Tunnel、ngrok、frp、端口映射五种做法与排错）。

## 7. 数据、备份与迁移

```
data/
├─ db.json                 全部配置、词库、签名元数据、累计计数
├─ secret.key              会话签名密钥（首次启动生成，勿外泄）
├─ media/                  签名 PNG、留影 JPEG
├─ exports/                导出与清屏前自动备份
└─ logs/                   按天日志（单文件 5MB 滚动）
```

- **手动备份**：复制整个 `data` 目录即可；建议活动结束后立即复制到移动硬盘。
- **后台导出**：数据导出页可下载 CSV（Excel 直接打开不乱码）与 JSON（完整字段）。
- **迁移**：把程序目录与 `data` 一起拷贝到新机器，保证 `data/secret.key` 一同迁移，否则后台需重新登录。
- **清屏**：会删除签名与媒体文件，并在 `data/exports/before-clear-<时间戳>.json` 留备份；累计计数不清零。
- **容量**：签名 PNG 约 60–200 KB，留影 JPEG 约 120–400 KB。3000 条含留影约 1.2 GB。

## 8. 性能与稳定性

| 措施 | 说明 |
| --- | --- |
| 自适应渲染 | 每 120 帧统计平均帧耗时，超过 28ms 自动降低画布倍率，低于 14ms 再逐级恢复 |
| 卡片上限 | 后台可设 8–200；建议 1080P 用 60–80，4K 用 40–72 |
| 媒体压缩 | 手机端签名导出宽度上限 1400px，留影 900px JPEG(0.85)；服务端再次校验大小 |
| WebSocket | 25s 心跳、70s 无响应断开、4MB 写缓冲保护；客户端指数退避重连 |
| 渲染看门狗 | 20s 无渲染帧（休眠唤醒 / 浏览器假死）自动刷新页面 |
| 数据安全 | 原子写盘（临时文件 + rename）、每 200ms 防抖落盘、退出时同步落盘、损坏文件自动备份重建 |
| 进程守护 | 未捕获异常记录后继续服务；5 次/短时间连续异常才退出，建议配合 systemd / 计划任务重启 |
| 弱网 | 手机端提交失败自动暂存 localStorage，恢复网络后按同一 `clientToken` 幂等补传，不会重复上墙 |

## 9. 二次开发与扩展

### 9.1 替换为 MySQL / Redis

`server/store.js` 的 `Store` 已把读写集中在少量方法中：`load / addSignature / listVisible / listSignatures / updateSignatureStatus / deleteSignature / clearAll / stats / exportJson / exportCsv`。替换步骤：

1. 新建 `server/store.mysql.js`，实现同名方法（签名元数据入库，图片仍可落盘或转对象存储）。
2. 在 `server/app.js` 中把 `new Store(...)` 换成新实现，保持返回值结构一致。
3. 媒体文件路径统一走 `/media/<filename>`，前端无需改动。

Redis 适合缓存 `listVisible` 与实时统计：在 `addSignature` 后 `INCR` 今日计数、`LPUSH` 最新签名，读取时优先命中缓存即可。

### 9.2 改造成微信小程序

现有接口已按 REST + JSON 设计，小程序端只需：

- 用 `wx.request` 替换 `fetch`（`public/js/lib/api.js` 可直接参考）。
- 手写签名用 Canvas 2D 接口，导出 `wx.canvasToTempFilePath`，再转 base64 调用 `POST /api/signatures`。
- 实时状态可用 `wx.connectSocket` 连接 `/ws`，发送 `{"type":"hello","role":"mobile"}`。

### 9.3 更换大屏引擎（Unity / Three.js）

大屏与后端仅通过 HTTP + WebSocket 通信，事件与数据结构见《接口文档》。引擎侧只需实现"接收 `signature:new` → 播放自己的上墙动画"即可平滑替换，服务端零改动。

### 9.4 定制 VI

- 颜色：后台「视觉与主题」直接改主强调色 / 纸张色，实时生效。
- 背景：`public/js/stage/background.js` 中 `THEMES` 定义了三套天空、山峦、雾色，可新增主题。
- 卡片版式：`public/js/stage/wallstage.js` 的 `LAYOUT` 与 `_buildTexture`。
- 海报版式：`public/js/lib/poster.js` 的 `drawPoster`。
- Logo：替换 `public/assets/favicon.svg` 与大屏 / 手机 / 后台中的内联 SVG。

## 10. 故障排查

| 现象 | 排查顺序 |
| --- | --- |
| 大屏打不开 | 服务是否运行（终端有启动日志）→ `http://localhost:8080/healthz` 是否返回 JSON → 端口占用（`netstat -ano | findstr 8080`） |
| 手机扫不出 / 打不开 | ① 手机与大屏是否同一 Wi-Fi；② 路由器是否开启 AP 隔离；③ 双击 `开放防火墙端口.bat` 放行端口；④ 后台「活动配置 → 对外访问地址」是否为 Wi-Fi 地址；⑤ 用手机浏览器直接输入 `http://<局域网IP>:8080/mobile` 验证 |
| 二维码地址是 192.168.x.x 但手机打不开 | 十有八九指向了 VMware / Hyper-V 虚拟网卡。打开后台「活动配置」，在「对外访问地址」下拉中选择 WLAN / 以太网对应的地址并保存；大屏会自动刷新二维码，右下角会显示当前指向的主机 |
| 二维码仍是 localhost | 未检测到局域网 IPv4 地址（只有回环）：检查网络连接是否正常，或在后台手动填写 `http://<局域网IP>:8080/mobile` |
| 手机页面能打开、提交失败 | 看提示：`RATE_LIMITED` 为提交过频（90 次/分钟/IP）；`TEXT_REJECTED` 为敏感词拒收；`NETWORK` 检查 Wi-Fi；页面会自动暂存并补传 |
| 签名提交失败 | 看提示：`RATE_LIMITED` 为提交过频（90 次/分钟/IP）；`TEXT_REJECTED` 为敏感词拒收；`NETWORK` 检查 Wi-Fi |
| 大屏不实时更新 | 右上角连接状态是否为「实时同步」；断线会自动重连；检查是否有代理拦截 WebSocket 升级 |
| 摄像头打不开 | 是否 HTTPS/localhost；浏览器地址栏摄像头权限；被其他程序占用；改用手机端"从相册选择" |
| 打印窗口没弹出 | 浏览器拦截弹窗 → 允许本站点弹窗；打印页需在 700ms 后加载完海报 |
| 海报保存失败（iPhone） | Safari 对 `download` 支持有限：长按海报 → 存储到照片 |
| 页面白屏 | 按 F12 看 Console；`#boot-error` 会显示错误摘要；尝试 Ctrl+F5；检查 `public/` 文件是否完整 |
| 事件后数据丢失 | 查看 `data/logs/server-*.log` 与 `data/db.json`；`data/exports/` 有清屏备份；`data/db.corrupt-*.json` 为损坏前备份 |
| 卡顿 / 掉帧 | 降低「最多同时展示数量」；4K 屏将浏览器缩放调到 100%；关闭其他占用 GPU 的程序 |

日志位置：`data/logs/server-YYYY-MM-DD.log`。

健康检查：`GET /healthz` 返回运行时长、连接数、签名数、内存占用，可接入监控。
